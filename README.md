# 🌙 Mkmoon — نظام التداول الورقي الحيّ (ICT-DAY-15M-SLM-01)

نظام توصيات وتداول **ورقي** بأسعار حية، ينفّذ الاستراتيجية المُتحقَّق منها من مرحلة
الباك-تست (M_DUAL — نظام مزدوج مُدمج) بشروط مطابقة حرفياً — ويُثبت التطابق باختبارات آلية.

> الحالة: تداول وقي (paper) بعائد مئوي مركّب — لا حساب رأس مال حقيقي،
> رأس المال افتراضي يبدأ 100% وينمو/ينكمش بالنسبة المئوية (مخاطرة 1% لكل صفقة).

## 1) الاستراتيجية المُعتمدة (مُجمَّدة — لا تُعدَّل أثناء التحقق)

| البند | القيمة |
|---|---|
| الإشارة | اندفاع (Sweep) سيولة + CHOCH/MSS أو استمرار (chain) → فجوة FVG |
| الدخول | أمر معلّق عند منتصف FVG (limit) |
| الوقف | طرف الـSweep ∓ 0.20 ATR |
| الإبطال المبكر | إغلاق 1m خارج حافة الفجوة |
| قفل الربح | MFE ≥ 1.5R ← الوقف إلى الدخول +1.2R (قفل عميق) |
| الهدف | 1.7R ثابت (معظم الأرباح تُقفل عند +1.2R رجعيًّا عند شريط المحفّز) |
| الإغلاق الزمني | 24 ساعة |
| شريحة R | 1.2% – 3% من سعر الدخول |
| الجلسات | بدون جلسة آسيا |
| التكاليف | 7.5bps لكل طرف + 2bps انزلاق خروج |
| الأطر | إشارات 15m (سياق 1h/4h)، تنفيذ 1m |
| الأزواج | Tier A = 10 أزواج مُتحقَّق (توصيات) + Tier B = 30 زوج "تجريبي/خارج التحقق" |

**أداء الباك-تست (7,790 صفقة، 10 أزواج، 2021-2026):** نسبة ربح 72.7%،
توقع +0.056R، PF 1.80، أقصى تراجع 3.74%، 4.2 صفقة/يوم.

**تعميم مُثبت (8 أزواج جديدة × 3 سنوات — خارج عيّنة البحث):**
4,950 صفقة، نسبة ربح 70.0%، توقع +0.045R، **8/8 أزواج موجبة**،
×9.33 على رأس المال الافتراضي (مخاطرة 1%)، أقصى تراجع لكل زوج ≤ 3.9%.
(التفاصيل: `ict_bt/results/generalization_8pairs_3y.json`)

## 3.1) تحدّي "الأرباح بين +1.0 و +1.7R" — النتيجة 🏆

**الهدف المعلن:** أن تصل الصفقات الرابحة إلى +1.0..+1.7R (وليس 0.3R)، مع بقاء
التوقع موجبًا على **15 زوجًا × سنوات متعددة** (2021-22 هبوط و2025-26). البروتوكول
مُعلَن مسبقًا: تدقيق أعمى خارج نطاق الاختيار (2021-09→2023-01 + 2025-01→2026-10)،
25 تهيئة (محفّز القفل 0.9..2.0R × فجوة 0.05..0.3R × هدف 1.0/1.5/1.7R)، تكلفة 17bps.

| التهيئة (الفاصلة) | G1 متوسط ربح | G2 الهدف | G3 15/15 | G4 توقع | G5 | dd |
|---|---|---|---|---|---|---|
| **t1.5_g0.3_tp1.7 → Y_LOCK12** | **+1.32R ✓** | +1.7R ✓ | ✓ | **+0.259R** | ✓ | 8.2% |
| t1.4_g0.1_tp1.7 | +1.16R ✓ | +1.7R ✓ | ✓ | +0.259R | ✓ | 6.9% |
| t1.3_g0.1_tp1.7 | +1.06R ✓ | +1.7R ✓ | ✓ | +0.258R | ✓ | **6.5%** |

- **المسار الواقعي لصفقة رابحة:** محفّز 1.5R يقفل +1.2R، وشريط المحفّز نفسه يُطبَّق
  عليه القفل رجعيًّا (متشائم كما في المحرك) فيخرج أغلب الفائزين عند **+1.2R صافي ≈ +1.05R**،
  وقلّة تصل هدف **+1.7R** — والمتوسط **+1.32R** داخل نطاق [+1.0, +1.7] المطلوب (92% من الفائزين في النطاق).
- **التكلفة الصادقة:** نسبة الربح تهبط 73% → **34%** (رابحة واحدة ≈ 4.5 خاسرة، والخسارة
  محدودة ≈ −0.30R بالإبطال المبكر). العائد ×5 مقابل Y_BAL35 (0.259R مقابل 0.050R).
- **العمومية مثبتة:** 15/15 زوجًا موجبون (0.16–0.34R)، و2022 الهبوطي +0.24R، وأسوأ شهر +0.02R.
- **منطقة ميتة مكتشفة:** أي تهيئة tp ≤ قفل+0.1R تنهار إلى −0.09R — هندسة سليمة فقط
  (tp ≥ قفل + 0.2R).

## 3.2) النظام المُدمج M_DUAL — سريع + ملموس 🎯⚡

بعد قياس **منحنى الحدودي** (حجم الفوز × معدله — جدول `research/c3_merge.json`) تبيّن
أن "70% فوز + أرباح 0.7-1.0R" خارج قدرات السوق (السقف ≈ 50%). **الحل المُدمج:**
كل إشارة → مركز واحد مقسوم نصفين:

| الجزء | الخروج | WR (أعمى) | الأرباح الصافية | الدور |
|---|---|---|---|---|
| ⚡ سريع (50%) | قفل +0.30R عند +0.35R، هدف +0.55R | **~70%** | +0.13 إلى +0.42R | دخل متكرر مُرضٍ |
| 🎯 ملموس (50%) | قفل +0.85R عند +1.0R، هدف +1.05R | ~32% | **+0.71 إلى +1.0R** | رابحة ملموسة 1–2/يوم |

- المحرّك المدمج: توقع **+0.058R** لكل 1% مخاطرة — وكل الصفقات تُدار لحظيًا (تنبيه فتح
  واحد يذكر الهدفين، وإغلاق منفصل موسوم لكل نصف مع السبب).
- البديل عالي العائد (موثق): قفل +0.90R@1.1R مع هدف +1.4R للنصف الملموس → توقع +0.148R
  مع أرباح تمتد أحيانًا إلى +1.26R.

## 4) الدورة (Cycle) وملخصها — ورأيي في اقتراحك

اقتراحتك: عدّاد دورة كل دقيقة + إشعار هل كل المفاصل سليمة ومترابطة.
**هذا مناسب ويُنفَّذ**، مع التنبيه التالي (ناقشتُه معك سابقاً):

- **الإشارات تُولَّد عند إغلاق الشموع فقط** (15m/1h/4h) — هذه شروط الاستراتيجية
  المُختبَرة نفسها؛ "إشارة" داخل الشمعة قبل إغلاقها تخرق سببية القواعد وتُنتج
  صفقات لم تُختبر قط.
- **لكن لا تضيع فرصة**: الأوامر المعلّقة تُراقب كل 3 ثوانٍ والتنفيذ لحظي بلحظي
  (SL/TP/قفل/إبطال = نبضات سعرية فورية). أي حركة سعر تلمس أمر معلّق = تعبئة.
- **الدقيقة** = وحدة المحاسبة: كل دقيقة يُكتب صف `cycle_reports` يوثّق حركة كل
  مفصل (أشواط الكاشف، الأوامر، التعبئات، حالة Redis/Supabase/Telegram/Binance
  وزمن استجابتها، الرام، الأخطاء) + حكم: "كل المفاصل تعمل بترابط ✓" أو قائمة
  الأعطال. زر «🧾 ملخص الدورة» يعرض آخر تقرير.
- **بدل 1440 رسالة/يوم**: نبض تلغرام ملخّص كل 30 دقيقة (قابل للضبط
  بـHEARTBEAT_MINUTES) + **تنبيه فوري فور حدوث أي عطل** — لا تدهور صامت أبداً.

## 5) أزرار التلغرام (5)

| الزر | المحتوى |
|---|---|
| 🟢 الصفقات المفتوحة | الصفقات المفتوحة (ربح/خسارة لحظي %) + الأوامر المعلّقة |
| 📕 الصفقات المغلقة | آخر الصفقات المغلقة **مع سبب الإغلاق والنتيجة %** |
| 📈 أداء النظام | صفقات، نسبة ربح، توقع R، رأس المال %، أقصى تراجع |
| 💹 الأسعار الحية | أسعار كل الأزواج الـ40 + تغير 24 ساعة |
| 🧾 ملخص الدورة | تقرير الدورة الأخيرة: حركة كل المفاصل + الاتصالات + الحكم |

**إشعارات دورة حياة كل صفقة:** توصية (دخول/وقف/هدف/نسبة%) → تأكيد الدخول لحظة
التعبئة → الإغلاق **مع ذكر السبب** (🎯 هدف / 🔒 قفل ربح / 🛑 وقف / ⚠️ إبطال /
⏱️ زمني) + النتيجة % + رأس المال بعدها. الصفقة تُتابَع من الفتح حتى النهاية دائماً.

## 6) النشر على Render (خطوة بخطوة)

1. **إنشاء الخدمة:** Render Dashboard → New → Web Service → ربط مستودع
   `mkkh01/Mkmoon` (الفروع: `main`). الإعدادات تُقرأ من `render.yaml` تلقائياً
   (build: `pip install -r requirements.txt` — start: `python -m app.main` —
   health check: `/health`). خطة **Free**.
2. **متغيّرات البيئة** (Environment — القيم الحساسة هنا فقط، لا في المستودع):

   | المتغيّر | القيمة |
   |---|---|
   | `REDIS_URL` | انسخ "Public endpoint" من لوحة Redis (⚠️ انظر التنبيه أدناه) |
   | `DATABASE_URL` | نص الاتصال من Supabase: Connect → Session pooler (postgresql://...) |
   | `SUPABASE_URL` | `https://dbkeszbmjvkpqljckfifa.supabase.co` |
   | `BOT_TOKEN` | توكن البوت من @BotFather |
   | `CHAT_ID` | معرّف محادثتك (كل الإشعارات والأزرار تُربط به) |
   | `HEARTBEAT_MINUTES` | 30 (أو 0 لإيقاف النبض الدوري) |
   | `STATUS_KEY` | كلمة سر `/status` (يولّدها Render تلقائياً من render.yaml) |
   | `TIER_B_ENABLED` | 1 (تشغيل الظل للأزواج التجريبية) |
   | `FILL_MODE` | `bar_close` (مطابق للباك-تست — الافتراضي) أو `instant` |

3. **التشغيل:** Deploy → بعد الإقلاع ستصلك رسالة "🌙 Mkmoon يعمل الآن" مع
   القائمة (أرسل /start إن لم تظهر).
4. **Keep-alive (cron-job.org):** أنشئ مهمة كل 10 دقائق على:
   `https://mkmoon.onrender.com/health`
   (أو `/run-cycle?key=...` لتفعيل دورة يدوية مع كل ping).
5. **مراقبة:** `https://mkmoon.onrender.com/status?key=YOUR_STATUS_KEY` —
   كل المفاصل + ميزانية البيانات + آخر دورة.

> ⚠️ **تنبيه Redis:** النطاق `crystalline-chatty-supersnug-13492.db.redis.io`
> **غير موجود في DNS عالمياً** (فحص NXDOMAIN عبر 8.8.8.8) — النظام سيعمل بدون
> Redis (حالة في الذاكرة + السجل في Supabase) لكن يُفضَّل إصلاحه: انسخ العنوان
> العام (Public endpoint) الصحيح من لوحة مزوّد Redis — إن كان بـTLS استعمل
> `rediss://`. النظام يعتمد Redis فقط كمسرِّع حالة/كاش أسعار.
